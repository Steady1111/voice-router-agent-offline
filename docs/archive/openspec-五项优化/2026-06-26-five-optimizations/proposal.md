# Proposal — 五项优化

> **参考文档**（非实现依据）。实现以 [design.md](./design.md) + [tasks.md](./tasks.md) 为准。

## 背景

voice-router-lite 已完成预研主干（Mac + ESP32 WebSocket、KWS→ASR→NLU→风扇控制、Web 控制台）。下一步在**不更换大模型架构**前提下，提升演示与量产可用性。

## 目标

| # | 优化项 | 目标一句话 |
|---|--------|------------|
| 1 | 语音识别 | 风扇语音控制稳定；路由器意图可验收 |
| 2 | 设备状态 | 网页只展示风扇+路由器，信息足够演示与运维 |
| 3 | 语音播报 | 有反馈即可；预研网页女声 TTS 兜底；预录 WAV 可延后 |
| 4 | 前端布局 | 用户视图简洁；调试能力保留 |
| 5 | 内存 | 128MB 路由器待机 ≤75MB，峰值 ≤88MB |

## 产品约束（已确认）

1. **网页必须保留**：预研监控指标 + 智能家居配套软件（主管/用户演示）
2. **路由器无屏**：即时反馈靠 **RGB 灯 + 语音**；网页负责状态与配置
3. **ESP32 继续参与**：风扇执行与展示（近期不改为纯 GPIO）
4. **Web 与 daemon 分进程**：语音守护进程崩了，网页仍可查状态
5. **无 Web 登录**：v1 仅局域网访问

## 不做什么

- 不采用 Paraformer / Whisper / LLM 语音架构
- 不做自然语言自由对话
- 不做外网远程访问、HTTPS、账号体系（v1）
- 不砍掉 Web 服务换内存
- 不在 v1 实现下联设备详情列表、Luci 复刻

## 成功标准（摘要）

- 风扇语音：开/关各 10 次，≥8 次成功
- 危险误执行（误重启等）：0 次
- 网页：用户视图仅风扇+路由两卡；`?debug=1` 可看监控
- 播报：内容与 `reply` 一致（WAV / 网页女声 / 蜂鸣均可）
- 指令采集：演示时自动落盘 ≥20 条，供 NLU 再训
- 唤醒：A 线能量（现 ESP32）与 B 线 KWS 并行推进
- 内存：达到 spec.md 硬线

## 录音与模型（澄清）

| 做什么 | 是否训练模型 | v1 是否要做 |
|--------|--------------|-------------|
| `audio_clips` 女声 WAV | 否，仅播放 | **否，可延后** |
| `asr_debug` 指令采集 | 间接：补 NLU 误听文本 + 规则 | **是，优先** |
| `kws_samples` 唤醒词样本 | 否，调 KWS 阈值/评估（不重训 sherpa） | B 线并行 |
| 重训 Zipformer ASR | — | **不做** |

## 阶段划分

| Phase | 重点 | 周期（估） |
|-------|------|------------|
| 1 | **指令采集**、KWS B 线、INT8、router-status API | 1 周 |
| 2 | 前端改版、NLU 再训、DAC 播放；TTS 录音可选 | 1 周 |
| 3 | 路由器上板、量产仅 KWS、72h 稳定性 | 1 周 |
