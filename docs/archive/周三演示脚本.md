# 周三演示脚本

> **演示日期**：2026-06-26（周三）  
> **听众重点**：唤醒 → 识别 → 意图分类（全离线链路）  
> **预计时长**：5 分钟  
> **演示页面**：`http://localhost:28080/?demo=1`（本机控制台）  
> **当前实现版本**：ESP32 **方案 1**（音量触发 → 单次采集 → ASR → NLU）

---

## 演示策略（定稿）

**两条轨道，各干一件事，不碰容易翻车的：**

| 轨道 | 用什么 | 展示什么 | 不做什么 |
|------|--------|----------|----------|
| **A · 路由器** | **文本框**或「路由器指令」下拉 | **意图分类**（③）为主；② 显示指令文字；① 显示 `「文本输入」` | ❌ ESP32 麦说路由器 ❌ 局域网 IP 下按住说话 |
| **B · 风扇** | **ESP32 全链路** | **唤醒 → 识别 → 意图 → 风扇转**（①②③ 全亮） | ❌ 只说唤醒不控风扇 ❌ 风扇调档等复杂句 |

**可选加分（非主线）**：用 **Chrome + localhost** 按住 🎙️ 说路由器指令——仅作「ASR→NLU 同链路」补充，翻车就回到文本框。

## 一、开场一句话

> 离线语音助手分三步：**唤醒、识别、意图分类**。路由器意图今天用文本稳定展示 NLU；ESP32 硬件演示风扇 **端到端**（音量唤醒 + 一次说完指令）。

## 二、演示前准备（15 分钟）

### 2.1 启动服务

```bash
cd /Users/duanduan/CodingFiles/voice-router-agent-offline

# 若端口占用先杀旧进程
kill $(lsof -t -i :28080) 2>/dev/null

VOICE_ROUTER_WEB_HOST=0.0.0.0 \
VOICE_ROUTER_WEB_PORT=28080 \
python3 -m voice_router_lite web
```

日志出现 `[ESP32] 方案1 已启动 peak=0.120 ...` 即 ESP32 链路就绪。  
**无需**再设 `VOICE_ROUTER_ENERGY_WAKE`（已改为方案 1 音量策略，见 `wake_policy.py`）。

### 2.2 打开控制台

```bash
# 必须用 Chrome / Safari，不要用 Cursor 内置预览（无麦克风）
open 'http://localhost:28080/?demo=1'
```

投屏给主管看 ESP32 状态时，可用 `http://<本机局域网IP>:28080/?demo=1`，但**按住说话请仍在 localhost 操作**。

`?demo=1` 与默认页相同，顶部始终显示三步流水线；助手回复下方有「意图：xxx（置信度 xx%）」。

### 2.3 硬件检查（ESP32 风扇）

| 项 | 期望 |
|----|------|
| 顶栏「风扇」圆点 | 绿色 |
| 设备状态 · ESP32 指示灯 | **绿灯 · 待机监听**（未唤醒时） |
| ESP32 四位数码管 | 在线 |
| 风扇 | 彩排时转一下 |

路由器侧 Mac 上是 **mock 执行**（回复带「模拟」），**意图分类照常展示**。

### 2.4 彩排清单（只练这 5 项）

- [ ] 文本「重启路由器」→ ① `「文本输入」` → ③ `router_reboot`
- [ ] 文本「WiFi密码多少」→ ③ `router_wifi_config`（或 `router_network_query` 也可接受）
- [ ] ESP32 **大声**说「**小T小T，打开风扇**」（尽量一句说完）→ ① `「小T小T」（volume）` + 设备区 **红灯** → 风扇转
- [ ] 冷却约 3s 后说「**小T小T，关闭风扇**」→ 风扇停
- [ ] 用网页麦说话时，ESP32 指示灯**保持绿灯**（不应误变红灯）

## 三、正式演示流程（约 5 分钟）

### 第 0 步：指界面（30 秒）

> 主管您关心的三条链路在顶部：**唤醒、识别、意图**。左侧设备状态看风扇/温度/ESP32 灯；右侧是路由器资源与性能监控。

**性能监控说明（若被问到 CPU）**：  
「CPU 占用」= 采样窗口内 **KWS/ASR/NLU 推理耗时占比估算**，不是 Mac 真实 CPU；空闲时接近 0% 正常。

---

### 第 1 步：意图分类 — 路由器（2 分钟）【轨道 A · 文本框】

在底部**文本框**或 **「路由器指令」下拉**依次发送（不要 ESP32 麦）：

| 输入 | 指着 ③ 说 | 预期意图 |
|------|-----------|----------|
| 重启路由器 | 「分类成重启意图」 | `router_reboot` |
| WiFi密码多少 | 「这是查 WiFi 配置/密码」 | `router_wifi_config` 或 `router_network_query` |

**讲解词**：

> 路由器场景先用文本输入，稳定展示 **NLU 意图分类** 和置信度。47 条路由器话术已在 Mac 朗读实录里做过 ASR 误听修正表，NLU 用 2500+ 条合成语料训练。Mac 上路由器动作是模拟执行，意图结果是真实的。

**意图展示看两处**：

1. 顶部 **「③ 意图」** — 主指这里  
2. 小 T 气泡下灰色字 — 「意图：router_reboot（置信度 xx%）」

**① 唤醒显示**：`「文本输入」`（无「跳过唤醒」字样）。

---

### 第 2 步：全链路 — ESP32 风扇（2 分钟）【轨道 B · 仅风扇】

**只做风扇，不说路由器。**

1. 对着 ESP32 麦**清晰、稍大声**说一句：  
   **「小T小T，打开风扇」**（推荐一句说完，含唤醒词 + 指令）
2. 观察：
   - 顶栏唤醒圆点变绿，① **`「小T小T」（volume）`**
   - 设备状态 · ESP32 指示灯 → **红灯 · 听指令中**（约 12s 内）
   - ② 显示 ASR 文字（可能是「打开封了」等误听，NLU 有兜底）
   - ③ `device_control`，风扇转
3. （可选）冷却 3s 后：**「小T小T，关闭风扇」** → 风扇停，指示灯回 **绿灯 · 待机监听**

**讲解词**：

> ESP32 负责采音和执行。当前演示用**音量门限**触发唤醒并一次录完整句，再走 ASR、NLU、下发风扇。路由器与风扇共用同一套 NLU，执行端不同。正式产品会以 KWS「小T小T」为主，音量唤醒是 ESP32 麦质量下的演示保底。

**若唤醒没反应**：再大声一点；或拆成两句间隔 >3s（不推荐）。**不要**在演示里单独炫 KWS。

**若 ASR 听错但仍控对风扇**：口头补一句「硬件麦 ASR 误听多，NLU 有关键词兜底」。

---

### 收尾（30 秒）

> 路由器意图分类已通；ESP32 风扇端到端已通。下一步是路由器量产麦 + KWS 微调 + MIPS 内存验收。

## 四、绝对不演示

| 不做 | 原因 |
|------|------|
| ESP32 说「重启路由器 / WiFi密码」 | ESP32 麦 ASR 极差，且链路为风扇专用 |
| 局域网 IP 页面按住说话 | 非安全上下文，浏览器禁用麦克风 |
| Cursor 内置浏览器按住说话 | 无 `getUserMedia` |
| 单独炫 KWS「小T小T」 | ESP32 上命中率不稳，当前方案不依赖 KWS |
| 「今天天气不错」 | NLU 易误分类 |
| 「风扇调到三档」 | ASR + 槽位易错 |
| 打开访客网络等长句 | 非必要，省时间 |

## 五、翻车预案（极简）

| 现象 | 应对 |
|------|------|
| ESP32 风扇整条翻车 | **轨道 A 文本框已够交差**；口头说「ESP32 麦 + ASR 预研中」 |
| 只唤醒风扇不转 | 改说「小T小T打开风扇」一句；或再说一次「打开风扇」 |
| 网页麦报「不支持麦克风」 | 换 Chrome 打开 `http://localhost:28080`，允许麦克风 |
| 指示灯一直红灯 | 强刷页面（`Cmd+Shift+R`）；确认不是网页按住说话误触（已修复） |
| 服务起不来 | `kill $(lsof -t -i :28080)`；确认 `models/asr` 存在 |
| 看不到三步条 | 页面已默认展示；可带 `?demo=1` |

**底线**：文本框两条路由器意图 **必须成功**；ESP32 风扇 **尽力一次**（开 + 关）。

## 六、主管追问（精简版）

**Q：路由器为什么打字？**  
A：今天重点是意图分类稳定可见；完整语音链路在 ESP32 风扇段演示。路由器 47 条话术在 Mac 麦上做过 ASR 对齐，ESP32/量产麦另验收。

**Q：音量唤醒算正式方案吗？**  
A：**演示保底**（方案 1）；量产以 **KWS「小T小T」** 为主，音量仅作 gate 或关闭。

**Q：为什么不用大模型？**  
A：128MB MIPS 跑不动；指令场景 NLU 足够。

**Q：47 条不是训练过了吗？**  
A：47 条是 **Mac 朗读实录 → ASR 误听修正表**；NLU 用更大合成语料训练。ESP32 麦误听不同，所以路由器不在 ESP32 上语音演示。

## 七、意图分类怎么指给主管看

输入或 ESP32 说完后：

```
① 唤醒  …
         文本框：「文本输入」
         网页麦：「网页麦克风」（可选）
         ESP32：「小T小T」（volume）  ← 仅风扇段
② 识别  …（显示 ASR/指令文字）
③ 意图  router_reboot 95%    ← 主指这里
```

再指助手回复下的「意图：…（置信度 …%）」作双保险。

## 八、界面与实现对齐（备忘）

| 界面元素 | 当前行为 |
|----------|----------|
| ① 唤醒 | 不再显示「跳过唤醒」 |
| ESP32 指示灯 | 仅 **ESP32 wake_detected** 时红灯；网页麦/文本不影响 |
| ESP32 采集 | 单次最长约 5s，静音 0.8s 结束，冷却 3s |
| 推荐口令 | 「小T小T，打开风扇」/「小T小T，关闭风扇」 |
| 可调 env | `VOICE_ROUTER_VOLUME_WAKE_PEAK`（默认 0.12）等，见 `wake_policy.py` |
