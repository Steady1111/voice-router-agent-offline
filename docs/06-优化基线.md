## 二、优化后架构

```
路由器 / Mac
  ┌──────────────────┐    ┌─────────────────────────────┐
  │ voice-router-web │◄──►│ voice-routerd (daemon)      │
  │ FastAPI :28080   │    │ KWS → ASR子进程 → NLU → TTS │
  └────────┬─────────┘    └───────────┬─────────────────┘
           │                          │
     浏览器 / 手机              ESP32（采音/风扇，可选）
```

Web 只读状态与对话展示；daemon 承担实时语音。

## 三、五项优化要点

### 1. 语音识别

- 预研：ESP32 PCM → WS → ASR → NLU；风扇误听兜底状态机  
- 指令采集工具与采集窗环境变量  
- 唤醒双线：A 线（能量/音量，现设备演示）∥ B 线（KWS，好麦/量产）

### 2. 设备状态面板

- 默认用户视图：风扇 + 路由器两卡  
- `?debug=1` 保留监控  
- `GET /api/router-status` 等状态 API

### 3. 语音播报

- v1：网页女声 / 蜂鸣即可  
- 量产再补 `audio_clips` WAV

### 4. 前端布局

- 用户视图简洁；调试能力保留在 debug 参数

### 5. 内存

- 128MB 硬线：待机 ≤75MB，峰值 ≤88MB，ASR 后 ≤76MB（待实机填实测）  
- INT8 NLU、ASR 子进程、可选 Native worker、模型互斥

## 四、验收标准摘要

| ID | 要点 |
|----|------|
| AC-1 风扇语音 | 开/关各 10 次 ≥8 成功；胡话不误触危险路由操作 |
| AC-2 网页 | 默认两卡；debug 可见监控；同 WiFi 可访问 |
| AC-3 反馈 | 有「已打开风扇」类反馈（女声或蜂鸣） |
| AC-3b 唤醒 | A 线能进指令；B 线正样本 ≥14/20，负 ≤2/10 误唤醒；量产仅 KWS |
| AC-4 内存 | 待机/峰值/回落满足硬线 |
| AC-5 进程 | 停 daemon 留 web 仍可查状态；启 daemon 后 running |

## 五、任务阶段摘要

### Phase 1（可并行）

| 主题 | 要点 |
|------|------|
| 1A 指令采集 | CLI、环境变量、落盘、`wake_source` |
| 1B TTS WAV | 可选延后 |
| 1C INT8 NLU | 导出 + 配置 prefer_int8 |
| 1D router-status | API + 前端 |
| 1E KWS B 线 | 样本目录、评估脚本、阈值 |

### Phase 2

前端改版、NLU 再训（样本足够后）、DAC 播放；TTS 录音可选。

### Phase 3

路由器上板、量产仅 KWS、72h 稳定性。

不在范围：换大模型架构、自由对话、外网 HTTPS/账号体系等（见归档 proposal）。
