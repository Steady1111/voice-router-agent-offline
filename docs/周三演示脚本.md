# 周三演示脚本

> **演示日期**：2026-06-26（周三）  
> **听众重点**：唤醒 → 识别 → 意图分类（全离线链路）  
> **预计时长**：5 分钟  
> **演示页面**：`http://<本机IP>:28080/?demo=1`

---

## 演示策略（定稿）

**两条轨道，各干一件事，不碰容易翻车的：**

| 轨道 | 用什么 | 展示什么 | 不做什么 |
|------|--------|----------|----------|
| **A · 路由器** | 文本输入框 | **意图分类**（③）为主；② 显示输入文字；① 标「跳过唤醒」 | ❌ ESP32 麦说路由器 ❌ 网页按住说话 |
| **B · 风扇** | **ESP32 全链路** | **唤醒 → 识别 → 意图 → 风扇转**（①②③ 全亮） | ❌ 只说唤醒不控风扇 ❌ 风扇调档等复杂句 |

## 一、开场一句话

> 离线语音助手分三步：**唤醒、识别、意图分类**。路由器指令用文本稳定展示 NLU；ESP32 硬件只演示风扇端到端全链路。

### 2.3 硬件检查（ESP32 风扇）

| 项 | 期望 |
|----|------|

| ESP32 四位数码管 | 在线 |
| 风扇 | 彩排时转一下 |

路由器侧 Mac 上是 **mock 执行**（回复带「模拟」），**意图分类照常展示**。

### 2.4 彩排清单（只练这 5 项）

- [ ] 文本「重启路由器」→ ③ `router_reboot`
- [ ] 文本「WiFi密码多少」→ ③ `router_wifi_config`
- [ ] ESP32 说话 → ① 变绿（`energy_wake` 即可）
- [ ] ESP32 唤醒后说「**打开风扇**」→ ③ `device_control`，风扇转
- [ ] 再说「**关闭风扇**」→ 风扇停（可选）

## 三、正式演示流程（约 5 分钟）

### 第 0 步：指界面（30 秒）

> 主管您关心的三条链路在顶部：**唤醒、识别、意图**。右侧是路由器和风扇状态。

---

### 第 1 步：意图分类 — 路由器（2 分钟）【轨道 A · 文本框】

在底部文本框**依次输入**（不要语音）：

| 输入 | 指着 ③ 说 | 预期意图 |
|------|-----------|----------|
| 重启路由器 | 「分类成重启意图」 | `router_reboot` |
| WiFi密码多少 | 「这是查 WiFi 配置」 | `router_wifi_config` |

**讲解词**：

> 路由器场景先用文本输入，让您稳定看到 **NLU 意图分类** 和置信度。量产里这段文字来自 ASR，链路相同。Mac 上路由器动作是模拟执行，意图结果是真实的。

**意图展示看两处**：

1. 顶部 **「③ 意图」** — 主指这里  
2. 小 T 气泡下灰色字 — 「意图：router_reboot（置信度 100%）」

---

### 第 2 步：全链路 — ESP32 风扇（2 分钟）【轨道 B · 仅风扇】

**只做风扇，不说路由器。**

1. 对着 ESP32 麦**说一句话**（或稍大声）→ 顶栏唤醒变绿，① 显示 `energy_wake`
2. 接着说「**打开风扇**」→ ② 显示识别文字，③ 显示 `device_control`，风扇转
3. （可选）再说「**关闭风扇**」→ 风扇停

**讲解词**：

> ESP32 负责采音和执行。走完唤醒、ASR 识别、NLU 分类，再下发给风扇。路由器与风扇共用同一套 NLU，只是执行端不同。

**若 KWS 没触发**：不用纠结，有 `energy_wake` 就够，口头补一句「正式产品以 KWS 小T小T 为主，能量唤醒是预研麦保底」。

---

### 收尾（30 秒）

> 路由器意图分类已通；ESP32 风扇端到端已通。下一步是路由器量产麦 + MIPS 内存验收。

## 四、绝对不演示

| 不做 | 原因 |
|------|------|
| ESP32 说「重启路由器」等 | ASR 易翻车 |
| 网页按住说话 | 本次不纳入脚本 |
| 单独炫 KWS「小T小T」 | ESP32 上命中率不稳 |
| 「今天天气不错」 | NLU 易误分类 |
| 「风扇调到三档」 | ASR + 槽位易错 |
| 打开访客网络等长句 | 非必要，省时间 |

---

## 五、翻车预案（极简）

| 现象 | 应对 |
|------|------|
| ESP32 风扇整条翻车 | **轨道 A 文本框已够交差**；口头说「硬件麦预研中」 |
| 风扇听错指令 | 只 retry「打开风扇」一次；再失败就跳过关闭 |
| 服务起不来 | `lsof -i :28080` 杀旧进程；确认 `models/` 存在 |
| 看不到三步条 | 确认 URL 带 `?demo=1` |

**底线**：文本框两条路由器意图 **必须成功**；ESP32 风扇 **尽力一次**。

## 六、主管追问（精简版）

**Q：路由器为什么打字？**  
A：今天重点是让您看清意图分类；语音链路在 ESP32 风扇段完整演示。路由器 ASR 在量产麦上验收。

**Q：能量唤醒算正式方案吗？**  
A：预研保底；量产 KWS 为主，能量唤醒关闭。

**Q：为什么不用大模型？**  
A：128MB MIPS 跑不动；指令场景 NLU 足够。

## 七、意图分类怎么指给主管看

输入或说完一句话后：

```
① 唤醒  …（文本框：跳过唤醒；ESP32：energy_wake）
② 识别  …（显示文字）
③ 意图  router_reboot 100%    ← 主指这里
```

再指助手回复下的「意图：…（置信度 …%）」作双保险。
