# 02 · 演示脚本

> 听众重点：唤醒 → 识别 → 意图分类（全离线）  
> 预计时长：约 5 分钟  
> 演示页：`http://localhost:28080/?demo=1`  
> 实现：ESP32 **方案 1**（音量触发 → 单次采集 → ASR → NLU）  
> 相关：[01-方案总览](./01-方案总览.md) · [03-部署手册](./03-部署手册.md)

---

## 一、演示策略

两条轨道，各干一件事：

| 轨道 | 用什么 | 展示什么 | 不做什么 |
|------|--------|----------|----------|
| **A · 路由器** | 文本框或「路由器指令」下拉 | 意图分类为主 | ESP32 麦说路由；局域网 IP 下按住说话 |
| **B · 风扇** | ESP32 全链路 | 唤醒 → 识别 → 意图 → 风扇 | 只唤醒不控扇；复杂调档句 |

可选加分：Chrome + localhost 按住说话演示 ASR→NLU；翻车即回文本框。

---

## 二、开场一句话

> 离线语音助手分三步：**唤醒、识别、意图分类**。路由器意图用文本稳定展示 NLU；ESP32 演示风扇端到端（音量唤醒 + 一次说完指令）。

---

## 三、演示前准备（约 15 分钟）

### 3.1 启动服务

```bash
cd /path/to/voice-router-agent-offline

kill $(lsof -t -i :28080) 2>/dev/null

VOICE_ROUTER_WEB_HOST=0.0.0.0 \
VOICE_ROUTER_WEB_PORT=28080 \
python3 -m voice_router_lite web
```

日志出现方案 1 相关启动信息即 ESP32 链路就绪。无需再设旧版能量唤醒开关。

### 3.2 打开控制台

```bash
# 必须用 Chrome / Safari（勿用无麦克风的内置预览）
open 'http://localhost:28080/?demo=1'
```

投屏可用局域网 IP，但**按住说话请在 localhost**。

### 3.3 硬件检查

| 项 | 期望 |
|----|------|
| 顶栏风扇圆点 | 绿色 |
| ESP32 指示灯 | 绿灯 · 待机监听 |
| 四位数码管 | 在线 |
| 风扇 | 彩排能转 |

路由器在 Mac 上为 **mock 执行**，意图分类仍真实展示。

### 3.4 彩排清单

- [ ] 文本「重启路由器」→ 意图 `router_reboot`
- [ ] 文本「WiFi密码多少」→ WiFi 配置/查询类意图
- [ ] ESP32 大声说「小T小T，打开风扇」→ 风扇转
- [ ] 冷却约 3s 后「小T小T，关闭风扇」→ 风扇停
- [ ] 网页麦说话时，ESP32 灯保持绿灯

## 四、正式流程（约 5 分钟）

### 第 0 步：指界面（30 秒）

指出顶部三步（唤醒 / 识别 / 意图）、左侧设备、右侧监控。  
若被问 CPU：监控为推理耗时占比估算，非本机真实 CPU。

### 第 1 步：轨道 A · 路由器意图（约 2 分钟）

用文本框或下拉发送：

| 输入 | 预期意图 |
|------|----------|
| 重启路由器 | `router_reboot` |
| WiFi密码多少 | `router_wifi_config` 或 `router_network_query` |

讲解：文本稳定展示 NLU；路由话术有 ASR 误听修正表；Mac 上动作为模拟。

### 第 2 步：轨道 B · ESP32 风扇（约 2 分钟）

只做风扇。清晰说：「小T小T，打开风扇」。观察唤醒、识别、意图、风扇与指示灯。可选再说关闭。

讲解：ESP32 采音与执行；当前演示音量门限；量产以 KWS 为主。

### 收尾（30 秒）

> 路由意图分类已通；风扇端到端已通。下一步：量产麦 + KWS 微调 + MIPS 内存验收。

## 五、绝对不演示

| 不做 | 原因 |
|------|------|
| ESP32 说路由指令 | 麦 ASR 差，链路为风扇向 |
| 局域网 IP 按住说话 | 非安全上下文，浏览器禁麦 |
| 内置预览按住说话 | 无麦克风权限 |
| 单独炫 KWS | ESP32 上不稳定 |
| 闲聊 / 复杂调档 / 过长句 | 易错、费时 |

## 六、翻车预案

| 现象 | 应对 |
|------|------|
| ESP32 整条失败 | 轨道 A 文本框交差 |
| 只唤醒不转 | 改为「小T小T打开风扇」一句再说 |
| 网页麦不可用 | Chrome + localhost 并允许麦克风 |
| 指示灯一直红 | 强刷页面 |
| 服务起不来 | 杀占用端口；确认 ASR 模型已下载 |

底线：文本框两条路由意图必须成功；风扇尽力开+关各一次。

## 七、主管追问要点

**为什么路由打字？**  
今天重点是意图可见；完整语音在风扇段；路由话术在 Mac 麦上对齐过，ESP32 麦另验。

**音量唤醒算正式方案吗？**  
演示保底；量产以 KWS「小T小T」为主。

**为什么不用大模型？**  
128MB MIPS 跑不动；指令场景 NLU 足够。

**朗读纠错和训练是一回事吗？**  
朗读纠错是 ASR 误听修正表；NLU 用更大合成语料训练。

## 八、界面与实现对齐

| 元素 | 行为 |
|------|------|
| ① 唤醒 | 文本输入 / 网页麦 / ESP32 volume，不显示「跳过唤醒」 |
| ESP32 灯 | 仅 ESP32 唤醒时红灯；网页麦/文本不影响 |
| 采集 | 单次约最长 5s，静音截断，冷却约 3s |
| 推荐口令 | 「小T小T，打开/关闭风扇」 |

环境变量细节见 [03-部署手册](./03-部署手册.md)。
